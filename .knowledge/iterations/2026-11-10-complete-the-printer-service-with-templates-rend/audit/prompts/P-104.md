# Task

Add the optional network module and wire the worker into a created or looked-up VPC, keeping
`vpc_mode = none` as the default and unchanged.

# Constraints

- `vpc_mode` accepts `none`, `create`, `lookup`.
- `create`: VPC with `vpc_cidr` and `az_count`; private subnets; optional public subnets and NAT
  (`enable_nat_gateway`); S3 gateway endpoint; SQS, Lambda and Events interface endpoints
  (optional); worker security group with outbound HTTPS/DNS and SQS/Lambda/Events access.
- `lookup`: resolve `vpc_id` or `vpc_tags`, and `subnet_ids` or `subnet_tags`; create no VPC.
- Printer module: VPC config on the Lambda only when a VPC is selected; output the resolved
  subnet/security-group IDs; no VPC config in `none`. Add the worker role's VPC execution
  permissions (`ec2:CreateNetworkInterface`, `DescribeNetworkInterfaces`,
  `DeleteNetworkInterface`) only when a VPC is selected, scoped to the network resources where
  AWS allows it.
- Root variables and tfvars example for all network inputs; README explains cost/endpoint/NAT
  trade-offs and that `none` is the default.
- Do not change Phase 1 resource names/outputs or the deploy policy assumptions.
- No apply and no real AWS calls. Use local/fake credentials for plan checks; validate all three
  modes.
- Follow the existing Terraform style; no `any`/untyped.

# Out of scope

- EventBridge ingress (`job_rule`), alarms, load test, cloud apply.
- Worker rendering/channel changes.

Write blockers and interface changes to `plan/prompts/_bus/outbox/P-104/`. Include the three-mode
