# Task

Author the first real generic template and add a local Chrome preview that uses the same page
settings the Lambda renderer will use in Slice 2.

# Constraints

- `templates/generic-report`: `template.json` with a fresh UUID v4, slug `generic-report`, name
  "Generic report", description; `index.html` is a semantic business report with `lang`, title,
  customer, `{{#each items}}`, totals and generated date; `styles.css` is self-contained; no
  external URLs, scripts or fonts. Use default sans-serif fonts so validation does not warn.
- `sample.json` contains generic synthetic data matching the placeholders; no customer/PII.
- Local renderer: `puppeteer-core` with an installed Chrome (`CHROME_PATH`, macOS default path,
  or `puppeteer` channel), launch per preview, close in `finally`; JavaScript disabled; request
  interception allows only `file:`, `data:` and `about:`; page.setContent with a `<base>` to the
  template directory so local CSS loads; A4, printBackground, preferCSSPageSize, tagged, header/
  footer with pageNumber/totalPages. Return `Uint8Array`.
- `template:preview` loads the descriptor, compiles with the engine (mode from `--strict`),
  renders through the local Chrome adapter, writes `.local/<slug>.pdf`, and prints the path. A
  missing Chrome or malformed data fails clearly. `--pdfa` is explicitly not available in Slice 1.
- Tests: use the real template + Chrome when available; skip with a clear message if `CHROME_PATH`
  and the default Chrome are absent. Unit-test the page settings and request policy without a
  browser where possible.
- Do not add dependencies; `puppeteer-core` is already in the catalog from P-101.
- Follow the shipped TypeScript examples; no `any`.

# Out of scope

- Lambda Chromium packaging, PDF/A, all channels, network, CI.
- No deployed changes.
