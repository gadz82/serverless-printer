# Task

Implement the Lambda adapter layer that turns SQS records into `ProcessPrintJob` calls, stores
the placeholder PDF in S3 and delivers the result to an SQS callback, including batch failure
reporting and the Phase 1 failure paths.

# Constraints

- Package name `@printer/render-worker`, ESM, executable by `nodejs24.x` Lambda with handler
  `handler.handler`.
- `src/config.ts` parses `PRINTS_BUCKET` (required), `HANDLEBARS_MODE` (`lenient` default;
  parsed but unused in Phase 1), `PDFA_ALLOWED_LEVELS` (comma list, default empty),
  `CALLBACK_ALLOWLIST` (JSON array, default `[]`), `EVENT_SOURCE` (default `printer`),
  `PRESIGN_TTL_SECONDS` (default 900), `MAX_RECEIVE_COUNT` (default 5) and
  `TEMPLATE_MANIFEST_PATH` (optional; defaults to the bundled manifest). Invalid values fail at
  cold start with a clear message and no secrets.
- The composition root passes an empty PDF/A allowed set to the use case regardless of the
  environment. Phase 1 must never return a non-PDF/A document labelled as PDF/A; if the env
  contains levels, log a warning that the placeholder cannot honour them.
- `TemplateCatalog` reads `templates.manifest.json`, validates its shape, resolves by exact id
  or slug, and supports the reserved `_smoke` slug.
- `PdfRenderer` returns a fixed valid minimal PDF (one page, `%PDF-` header, correct xref). It
  must be dependency-free and deterministic; it does not read the template or payload. Document
  it as the Phase 1 placeholder behind the port.
- `PrintRepository.store` writes `prints/<printId>.pdf` with `Content-Type: application/pdf`,
  computes SHA-256 over the bytes, returns the byte size, and presigns a GET for
  `PRESIGN_TTL_SECONDS`.
- `ResultDelivery.deliver(result, context)` converts the SQS queue ARN to a queue URL for the
  configured region, sends the JSON result body, and for `.fifo` queues sets:
  - `MessageGroupId` = `refId` when it is a string of at most 128 characters, otherwise the
    SHA-256 hex of a stable serialization of `refId`;
  - `MessageDeduplicationId` = SHA-256 hex of the stable serialization of `refId` concatenated
    with the inbound message id.
- The handler:
  - parses each SQS record body as JSON and validates it with `@printer/contracts`;
  - maps a valid job to the domain `PrintJob` and calls `ProcessPrintJob` with
    `attempt = ApproximateReceiveCount` and `maxAttempts = MAX_RECEIVE_COUNT`;
  - on invalid JSON or schema failure, attempts a failure result only when a readable failure
    webhook exists; otherwise reports the item failure so it reaches the DLQ;
  - returns `{ batchItemFailures: [{ itemIdentifier: messageId }] }` for retryable failures
    before the last attempt and for last-attempt delivery failures;
  - returns an empty failure list after a success or a delivered terminal failure;
  - never deletes messages directly.
- Logger: structured JSON with `printId`, `templateId`, `messageId`, attempt, error code and
  duration only. Never log `refId`, payload, HTML or PDF bytes.
- Use `composition-root.ts` as the only wiring point; no service locator or module-level
  clients that escape it.
- Follow `hexagonal-port.ts`, `domain-service.ts`, `composition-root.ts` and `style-example.ts`.
- Steering: `architecture-boundaries`, `solid-principles`, `dependency-inversion-container`,
  `architecture-hexagonal`, `code-style`, `code-examples`, `repository-flow`.
  `saga-pattern` is not applicable.
