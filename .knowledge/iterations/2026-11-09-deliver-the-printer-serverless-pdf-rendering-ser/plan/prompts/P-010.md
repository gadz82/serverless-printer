# Task

Implement the release path: semantic-release computes a release, the worker zip is built and
uploaded, Terraform deploys it through GitHub OIDC, and a real `_smoke` job proves the deployed
queue → worker → storage → SQS callback path; the same workflow can roll back to an earlier
release.

# Constraints

- Triggers: push to `main` and `workflow_dispatch` with an optional `release` string input.
  Concurrency group `deploy` with `cancel-in-progress: false`.
- Permissions: `contents: write` for semantic-release and the release asset, `id-token: write`
  for OIDC, `actions: read`.
- On push: checkout full history, setup Node 24 and pnpm 10.34.9, install, run semantic-release
  with `GITHUB_TOKEN`. `.releaserc.json` uses commit-analyzer, release-notes-generator,
  changelog, exec (`node scripts/write-release.mjs ${nextRelease.version}`), git (CHANGELOG.md,
  message `chore(release): ${nextRelease.version} [skip ci]`) and github. No npm publish.
- Determine the release: workflow_dispatch input if present; else `v` + `.release-version` when
  semantic-release wrote it; else `sha-` + the short SHA.
- On push, always build and upload: `RELEASE=<release> pnpm build:worker`, then
  `aws s3 cp dist/render-worker.zip s3://$ARTIFACTS_BUCKET/$RELEASE/render-worker.zip`. On a
  rollback dispatch, skip build and upload.
- Configure AWS credentials with `aws-actions/configure-aws-credentials` using
  `vars.AWS_DEPLOY_ROLE_ARN` and `vars.AWS_REGION`; no static keys.
- Terraform: init the S3 backend from `vars.TF_STATE_BUCKET`/`vars.TF_STATE_KEY`, then
  `terraform apply -auto-approve -var release=<release> -var artifacts_bucket=$ARTIFACTS_BUCKET`
  plus the operator's `-var-file=infra/terraform.tfvars` when present.
- Smoke: run `node scripts/smoke-test.mjs` with the jobs queue URL and smoke queue URL/ARN from
  Terraform outputs. The script sends one `_smoke` job with an SQS success callback, polls for a
  matching `refId` for up to 60 seconds, asserts `success`, `template.slug == "_smoke"`,
  `sha256` and `sizeBytes`, deletes the message and exits non-zero on timeout or failure.
- On a SemVer release, attach `templates.manifest.json` to the GitHub Release with
  `gh release upload` (clobber allowed). On a `sha-` release, skip the asset.
- Rollback: dispatch with an earlier release; skip semantic-release and build/upload; run apply
  and the smoke test. The workflow must not delete or retag releases.
- `scripts/build-worker.mjs`: generate the manifest with the current release, bundle
  `apps/render-worker/src/handler.ts` with esbuild (`platform: node`, `format: esm`,
  `target: node24`, `bundle: true`), copy the manifest and templates into `dist/`, and zip
  `dist/` to `dist/render-worker.zip` using the `zip` CLI. Fail if required files are missing.
- `scripts/write-release.mjs` writes `.release-version` without a trailing newline surprise.
- Add `.release-version` to `.gitignore` (P-001 already does); do not commit build output.
- Steering: `repository-flow`, `repository-trunk-based`, `code-style`.
