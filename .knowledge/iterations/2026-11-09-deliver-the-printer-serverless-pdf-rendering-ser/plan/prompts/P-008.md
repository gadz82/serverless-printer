# Task

Implement the printer Terraform module and the single root deployment that creates the queue,
transient storage, worker and permissions, and deploys the worker zip for a given release.

# Constraints

- Terraform `>= 1.11`, AWS provider `~> 6.0`; one root deployment, no environments or workspaces.
- Backend: S3, key `printer/terraform.tfstate`, `use_lockfile = true`. Backend values come from
  bootstrap outputs supplied at init time; do not hard-code an account.
- Module variables follow §6.5 with the spec defaults, plus `release`, `artifacts_bucket` and
  `name_prefix`. `pdfa_allowed_levels` defaults to `[]` in Phase 1 (ADR-003). `vpc_mode`
  defaults to `none` and validates that only `none` is supported until Phase 2.
- Jobs queue: SSE-SQS, visibility timeout at least 6× the 60 s timeout, redrive to DLQ after
  `max_receive_count` (default 5). DLQ is SSE-SQS.
- Queue policy: send only from `allowed_sender_account_ids`, `allowed_sender_principal_arns` or
  `organization_id`; include the optional EventBridge rule principal only if `job_rule` is
  supplied in a later increment.
- Smoke results queue: SSE-SQS, short retention, output URL and ARN. The worker's callback target
  set includes it automatically so the release smoke can complete.
- Prints bucket: SSE-KMS with a project CMK, public-access block, TLS-only policy, versioning off,
  lifecycle expiration after 1 day, worker-only write. KMS key rotation enabled and key policy
  scoped to the worker and deploy roles.
- Worker Lambda: `nodejs24.x`, `x86_64`, 1,536 MB, 60 s, handler `handler.handler`, code from
  `s3://<artifacts>/<release>/render-worker.zip`, published version plus `live` alias.
- Environment: `PRINTS_BUCKET`, `HANDLEBARS_MODE`, `PDFA_ALLOWED_LEVELS` (empty default),
  `CALLBACK_ALLOWLIST`, `EVENT_SOURCE`, `PRESIGN_TTL_SECONDS`, `MAX_RECEIVE_COUNT`. Keep the
  total under 4 KB.
- Event source mapping: batch size default 5 (1–5), `ReportBatchItemFailures`,
  `scaling_config.maximum_concurrency` default 10 with a minimum of 2, optional reserved
  concurrency. Point at the `live` alias.
- IAM worker: consume the jobs queue, read/write `prints/*`, KMS, logs, and `sqs:SendMessage` only
  on `callback_target_arns`; add `aws:ResourceOrgID` when `organization_id` is set. No wildcard
  resource for SQS send.
- CloudWatch log group with `log_retention_days` default 30; DLQ-depth and worker-error alarms
  behind `enable_alarms = false`, published to `alarm_sns_topic_arn` when enabled.
- Root variables mirror §6.5; `terraform.tfvars.example` documents every required operator
  value. Outputs: jobs queue URL/ARN, DLQ URL/ARN, prints bucket, smoke queue URL/ARN, function
  name and alias ARN.
- Install Terraform ≥ 1.11 and tflint if missing; do not commit binaries. Commit
  `infra/.terraform.lock.hcl`.
- Steering: `repository-flow`, `repository-trunk-based`, `code-style`.

# Out of scope

- `infra/bootstrap`, CI, release workflow, smoke script and LocalStack.
- VPC, network module, EventBridge ingress, Chromium, PDF/A and non-SQS channels.
- No dependency outside the P-001 catalog.
