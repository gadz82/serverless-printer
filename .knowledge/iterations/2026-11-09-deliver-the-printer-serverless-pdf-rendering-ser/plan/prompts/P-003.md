# Task

Implement the framework-free domain and the `ProcessPrintJob` use case that turns one validated
job into one stored print or one explicit failure, using only ports.

# Constraints

- No imports from `@aws-sdk/*`, `aws-lambda`, `node:fs`, `node:http`, `node:https`, Chromium or
  `@printer/render-worker`. The ESLint boundary rule from P-001 must pass.
- `ProcessPrintJob.execute` receives `{ messageId, job, attempt, maxAttempts }` plus injected
  `supportedChannels` and `pdfaAllowedLevels`. It must:
  1. reject a requested `pdfA` level outside the allowed list with `PDFA_LEVEL_NOT_ALLOWED`;
  2. reject an unsupported success/failure channel with `CALLBACK_NOT_ALLOWED` before rendering;
  3. resolve the template or fail with `TEMPLATE_NOT_FOUND`;
  4. render through `PdfRenderer`, store through `PrintRepository`, build the success result and
     deliver through `ResultDelivery`;
  5. map non-retryable errors to a delivered failure result;
  6. rethrow retryable errors before the last attempt;
  7. on the last attempt, deliver a failure result; if that delivery fails, rethrow so SQS can
     dead-letter the message.
- `printId` comes from `IdGenerator.forMessage(messageId)`; `refId` is copied unchanged.
- The success result carries `template { id, slug, contentHash, release }`, `pdfA: null` in
  Phase 1, `sha256`, `sizeBytes`, `printing`, `printingExpiresAt` and `renderedAt`.
- The failure result carries `template` or `null`, `error { code, message, retryable, attempts }`
  and `failedAt`.
- `TemplateDescriptor` owns `id`, `slug`, `contentHash`, `release`, `bundlePath` and the payload
  context is passed separately.
- `PdfRenderer.render` returns `Uint8Array`; the domain does not know about Chromium or files.
- Use the shipped examples `hexagonal-port.ts`, `domain-service.ts` and `domain-service.test.ts`
  for the port, use-case and test seam shapes.
- Steering: `architecture-boundaries`, `solid-principles`, `dependency-inversion-container`,
  `architecture-hexagonal`, `code-style`, `code-examples`. `saga-pattern` is not applicable.

# Out of scope

- Any AWS adapter, manifest reader, PDF bytes, config parsing or Lambda handler.
- Contract schema generation.
- No dependency outside the P-001 catalog.
