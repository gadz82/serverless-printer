# Task

Replace the Lambda placeholder renderer with a real Chromium adapter while keeping the local
preview on the same page settings.

# Constraints

- Add `@sparticuz/chromium` `153.0.0` and `pdf-lib` `^1.17.1` to the pnpm catalog and the worker
  package. Pin `puppeteer-core` to `25.11.0` (its bundled Chrome revision is 153, matching
  @sparticuz/chromium 153). No other dependency.
- One Chromium launch per instance; a new page per job; relaunch after a crash; always close.
- Use a render deadline below the 60 s Lambda timeout (50 s default, injectable). Bound launch,
  `newPage`, render and close with timeouts; skip `browser.close()` when the browser is already
  disconnected; preserve the original render error when cleanup fails.
- Detect page crashes/target-closed protocol errors even when the browser stays connected, and
  relaunch/retry once.
- `setJavaScriptEnabled(false)`; request interception allows only bundled files and data URIs;
  reject every network scheme.
- Page settings match the local renderer: A4, printBackground, preferCSSPageSize, tagged, header/
  footer with pageNumber/totalPages, A4 margins.
- The renderer returns PDF bytes and maps launch/render/timeout failures to retryable
  `PDF_RENDER_FAILED` at the adapter boundary; a 60s function timeout applies.
- Local preview keeps using installed Chrome; share the settings/policy helpers, not the Lambda
  binary.
- No PDF/A here; no channel changes.

# Out of scope

- PDF/A, channels, allowlist, roles, alarms, load tests.
- No deployed changes.
