# Task

Implement the four remaining result channels and ping behind the existing delivery port.

# Constraints

- HTTP: POST JSON, `X-Printer-Print-Id`, 5 s timeout, any 2xx delivered; allowlist/DNS policy from
  P-203 first.
- Lambda: `Invoke` with `InvocationType=Event`; body is the result.
- SQS: preserve FIFO identifiers; send result JSON.
- EventBridge: `PutEvents` with `EVENT_SOURCE` (default printer) and
  `printer.print.succeeded|failed`; detail is the result.
- S3: PUT PDF with `Content-Type: application/pdf` to the presigned URL; omit
  `printing`/`printingExpiresAt`.
- Ping after channel delivery: POST `{success: true|false}` to `pingUrl`, through the same policy;
  a ping failure is logged, not a result-delivery failure.
- Use AWS SDK v3 clients behind the composition root; no globals. Use Node `fetch` for HTTP/S3.
- Map failures to the existing retryable/terminal delivery errors; do not log URLs/refId.
- Wire the full worker runtime in the composition root: add `@printer/template-engine` to the
  worker package, compile the resolved template HTML with the configured mode, use
  `ChromiumPdfRenderer`, apply the `PdfArchiver` when `pdfA` is requested, pass the configured
  PDF/A allowed levels, and select the five channel adapters. Keep the local preview on its
  installed-Chrome adapter.
- Apply the P-203 CallbackPolicy to both success/failure HTTP targets and every ping URL. Pin the validated DNS address in the actual HTTP request (or revalidate immediately before connect) and disable redirects/revalidate each hop.
- Preserve `CallbackNotAllowed` through the use-case delivery path instead of wrapping it as retryable `DeliveryFailed`; validate both success and failure targets. The S3 presigned URL is intentionally skipped by the callback policy per the contract.
- Do not edit Terraform; P-207 supplies channel IAM.

# Out of scope

- Renderer/PDF-A adapter implementation (wiring is in scope); role modes, alarms.
- No new dependency beyond @printer/template-engine.
