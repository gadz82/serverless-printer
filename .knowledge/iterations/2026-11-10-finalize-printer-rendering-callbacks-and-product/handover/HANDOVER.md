# Handover — final rendering, callbacks and production readiness

- Iteration: `2026-11-10-finalize-printer-rendering-callbacks-and-product`
- Status: closed; G8 handover review
- Approved scope: SPEC Slices 2+3 in one iteration (ADR-202), delivered as 11 prompts
- Integration target: `main`; no feature branch remains

## What changed and why

Printer now implements the production contract: real Chromium rendering in Lambda, PDF/A
post-processing, all five callback channels with ping and SSRF protection, generated-or-provided
caller/worker roles, opt-in alarms and runbook, a plain/PDF-A render regression, the Chromium
release package, plain/PDF-A smoke, load/Power Tuning harness and the first-cloud verification
checklist.

The previous iteration delivered templates, the local preview and the optional network. This
iteration replaces the placeholder renderer and SQS-only delivery, and adds the production and
operational evidence path.

## Architecture delta

- `apps/render-worker/src/rendering/chromium-pdf-renderer.ts` — Lambda Chromium adapter with a
  50 s deadline, one launch per instance, page per job, crash retry and bounded cleanup.
- `apps/render-worker/src/rendering/{page-settings,request-policy,render-page,html-document}.ts` —
  shared A4/header/footer/tagged settings and bundle/data-only request policy for Lambda and local
  preview.
- `apps/render-worker/src/rendering/template-pdf-renderer.ts` — manifest bundle resolution,
  Handlebars compilation and the Chromium bridge.
- `apps/render-worker/src/pdfa/**` — pdf-lib archiver, eight level profiles, UTF-8 XMP, sRGB ICC,
  metadata consistency and safety checks.
- `apps/render-worker/src/security/**` — callback allowlist, DNS/SSRF policy and address
  classification.
- `apps/render-worker/src/delivery/**` — HTTP/Lambda/SQS/EventBridge/S3 adapters, pinned HTTP/S3
  transports, router, ping and invalid-message callbacks.
- `packages/domain/src/ports/pdf-archiver.ts`, `pdf-destination.ts` and the `ProcessPrintJob`
  changes — PDF/A and S3 PDF delivery behind ports.
- `infra/modules/printer/{iam,lambda,variables}.tf`, `infra/{main,variables}.tf`,
  `infra/bootstrap/iam.tf` — role modes, channel permissions, PassRole/GetRole, EC2/VPC
  permissions, worker memory and all-eight PDF/A defaults.
- `scripts/{build-worker,smoke-test,render-regression,load-test}.mjs`,
  `.github/workflows/{ci,release}.yml`, `tests/render/**` — packaging, smoke, regression and
  capacity evidence.
- `docs/{runbook,cloud-verification,load-test}.md`, `README.md`, `infra/README.md` — operator and
  maintenance documentation.

## Decisions and rejected alternatives

- **ADR-201** — separate caller and worker roles, each generated by default or provided; rejected
  a shared role because it would merge publish and consume permissions.
- **ADR-202** — deliver Slices 2+3 in one iteration with a G4 split fallback; no split was needed.
- **Chromium 153 pairing** — `@sparticuz/chromium@153.0.0` with `puppeteer-core@25.11.0`; rejected
  a newer puppeteer that bundles a different Chromium major.
- **PDF/A best effort** — pdf-lib plus the ICC-published sRGB2014 profile; rejected binary
  archivers, runtime downloads and any validator claim.
- **Single callback policy** — allowlist + DNS/SSRF, pinned addresses and no redirects for HTTP and
  S3; rejected trusting `fetch` DNS resolution or following redirects.
- **Render regression references** — real Lambda Chromium on Linux x86_64 with poppler; rejected
  local-Chrome references and screenshot-only tests.
- **Packaging** — externalize Chromium and copy its full runtime closure; rejected a custom image
  and a layer.

The example `annual-statement` in `SPEC.md` is illustrative only; the real template is
`generic-report`.

## How to run and test

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm lint
pnpm exec prettier --check .
pnpm template:validate
pnpm build:worker
pnpm test:render              # Linux x86_64 + poppler; skips locally otherwise
RENDER_REGRESSION_REQUIRED=1 pnpm test:render
pnpm test:integration         # LocalStack
terraform -chdir=infra fmt -check -recursive
terraform -chdir=infra init -backend=false -input=false
terraform -chdir=infra validate
tflint --config="$PWD/tflint.hcl" --chdir=infra --call-module-type=all
terraform -chdir=infra/bootstrap fmt -check -recursive
terraform -chdir=infra/bootstrap validate
orchid-sdd lint
orchid-sdd index --check
```

The render regression needs Linux x86_64, `@sparticuz/chromium` and poppler-utils. CI runs it on
`ubuntu-latest`; local macOS runs skip the two render tests by design.

## How to deploy and verify

1. Apply/re-apply `infra/bootstrap` with the current repository; it adds the caller role,
   EC2/VPC permissions and PassRole/GetRole.
2. Set the GitHub repository variables (`TF_VARS`, `AWS_DEPLOY_ROLE_ARN`, `AWS_PLAN_ROLE_ARN`,
   `AWS_REGION`, `TF_STATE_BUCKET`, `ARTIFACTS_BUCKET`).
3. Push to `main` or dispatch `release.yml`. The workflow builds the ~74 MB zip, uploads it,
   applies Terraform through OIDC, then runs plain and PDF/A-2b smoke jobs.
4. Follow `docs/cloud-verification.md` for branch protection, VPC checks, alarm test, load/Power
   Tuning evidence and the evidence record.

## How to roll back

- Dispatch `release.yml` with an earlier release label; the artifact must already exist. Both
  smoke jobs run, and an alias check confirms the rollback version.
- Manual fallback: `terraform -chdir=infra apply` with the earlier release and the same `TF_VARS`.
- A release predating PDF/A will fail the PDF/A smoke by design; choose a release that supports
  it, or document the accepted gap.
- No database or persistent business data is involved; prints expire from S3.

## Decisions the next owner should keep

- Keep caller and worker roles separate; do not merge their policies.
- Keep the callback allowlist/SSRF/pinned-address path for HTTP and S3; do not replace it with
  bare `fetch`.
- Keep PDF/A labelled as best effort; do not claim validation.
- Keep the render references environment-pinned to Linux x86_64/Chromium 153/poppler; refresh
  them only for intentional rendering changes.
- Keep `PDF/A-2b` in `pdfa_allowed_levels`; the release smoke requires it.

## Risks, gaps and follow-ups

- **Operator-only cloud evidence:** first apply, live plain/PDF-A smoke, rollback, branch
  protection/release-bot bypass and SNS alarm test remain unrun.
- **Candidate target:** 10 20-page jobs/min with p95 < 30 s must be confirmed by the first
  load/Power Tuning run.
- **PDF/A best effort:** no validator; part-1/a edge cases remain best effort.
- **Packaging is release-time validated:** add `build:worker` to PR CI if regressions become
  frequent.
- **Shared smoke queue retention** is five minutes; use a dedicated results queue for long load
  tests.
- **Local preview message:** `scripts/template-preview.mjs` still says "Slice 2" for `--pdfa`;
  local PDF/A preview is intentionally unavailable.
- **Branch protection state** is external to the repository; verify it with a real `main` push.
