# ChromiumPdfRenderer

## Behavior

Launches the bundled @sparticuz/chromium once per instance, renders one page per job with JavaScript disabled and request interception, and returns PDF bytes. A crash or target-closed error discards the browser and retries once; launch, page, render and close are deadline-bounded and cleanup never masks the original error.

## Why

Lambda needs a real Chromium behind the PdfRenderer port without leaking browsers across jobs. A 50 s render deadline stays below the 60 s function timeout, leaving room for cleanup.

## Invariants

- One browser per instance and one page per job; pages and browsers are always closed.
- Launch, page creation, rendering and cleanup are bounded by the render/close deadlines.
- JavaScript is disabled and only bundled file/data/about requests are allowed.
- A disconnected browser is not closed again, and cleanup failures preserve the original render result.

## Failure modes

Missing or failed Chromium launches, render timeouts and page crashes map to retryable PdfRenderFailed so SQS can redeliver.
