# Build worker

## Behavior

Bundles handler.ts with esbuild while externalizing @sparticuz/chromium, copies the full Chromium package and its resolved tar-fs/bare-* runtime closure, templates, manifest and sRGB ICC, then asserts the zip contents, closure import, size limits and handler export.

## Why

The Lambda package must contain the real Chromium binary and every runtime dependency as real directories; a successful esbuild alone does not prove the zip can launch Chromium.

## Invariants

- Chromium is external and its bin/ archives are present in the zip.
- All 19 runtime closure packages are copied as real files, not symlinks.
- The createRequire banner and handler import check remain.
- The zip stays above the Chromium size floor and below the Lambda unzipped limit.

## Failure modes

Missing Chromium files, unresolvable dependencies, an undersized/oversized payload or a handler without an export fail the build before upload.
