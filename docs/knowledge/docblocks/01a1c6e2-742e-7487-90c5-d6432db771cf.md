# ResultDeliveryRouter

## Behavior

Dispatches a result by webhook channel to HTTP, Lambda, SQS, EventBridge or the S3 PDF destination, applies the callback policy before HTTP delivery, and sends the optional ping after a successful or failed delivery.

## Why

The use case should depend on one ResultDelivery port while channel-specific payloads, headers, timeouts and security remain at the adapter edge.

## Invariants

- The selected channel matches the result's success/failure webhook.
- HTTP and ping targets pass the callback policy.
- S3 deliveries upload PDF bytes, not the JSON result.
- Ping failures are logged separately and do not change the delivered result.

## Failure modes

Unsupported channels and malformed targets fail explicitly; channel errors preserve the retryable/terminal contract.
