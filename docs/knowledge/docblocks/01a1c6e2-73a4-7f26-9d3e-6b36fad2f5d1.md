# PdfLibPdfArchiver

## Behavior

Loads a rendered PDF with pdf-lib, rejects encryption, JavaScript and unembedded fonts, then applies the requested PDF/A version, document ID, sRGB output intent, UTF-8 XMP part/conformance and consistent Info/CreatorTool metadata. Every level from PDF/A-1b through 3a is supported; conformance remains best effort.

## Why

Chromium cannot emit PDF/A, so the archiver adds the archival metadata behind the PdfArchiver port without claiming validator-grade conformance.

## Invariants

- Unsafe PDFs fail before any metadata is written.
- XMP is a UTF-8 stream and pdfaid:part/conformance match the requested level.
- The ICC profile and CreatorTool are consistent across all levels.
- The PDF header version is rewritten to the level's required version.

## Failure modes

Malformed input, unsafe features or pdf-lib errors map to non-retryable PDFA_CONVERSION_FAILED.
