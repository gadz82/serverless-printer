# pinnedHttpRequest

## Behavior

Sends an HTTP request to one of the pre-validated addresses from CallbackPolicy, preserving the original Host header and path, with a bounded timeout and redirects treated as errors. It tries the validated addresses in order within the same budget.

## Why

Resolving DNS again inside fetch would reopen the rebinding/TOCTOU gap between policy validation and the actual connection.

## Invariants

- The socket is pinned to a validated address; DNS is not resolved again.
- Redirects are not followed.
- The request timeout is shared across address attempts.
- Errors and bodies are surfaced without logging full URLs.

## Failure modes

No validated address, connection errors and timeouts surface as delivery errors for the channel to map.
