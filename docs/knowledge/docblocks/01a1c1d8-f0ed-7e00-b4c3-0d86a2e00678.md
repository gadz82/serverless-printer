# ProcessPrintJob

## Behavior

Validates PDF/A and channel support, resolves the template, renders and stores the PDF, then delivers a success or terminal failure with deterministic ids and timestamps.

## Why

One message must produce exactly one print or one explicit failure, independent of AWS, Chromium or transport details.

## Invariants

- printId is derived from the inbound message id.
- refId is echoed unchanged.
- Retryable errors rethrow before the last attempt.

## Failure modes

Non-retryable errors deliver a failure result; missing failure callbacks escalate so the queue can dead-letter; delivery failures propagate.
